终端响铃模式

沿用你平常的 SSH 会话。服务器发出响铃信号，本地 VS Code 播放内置提示音。配置完成后无需让回响保持打开；SSH 断开后不再提醒。

此模式不使用回响的音量、提示音或系统通知。向导不会登录服务器或修改配置，下面的勾选是你的手动验证记录，仅保存在当前管理界面。

1 · 在本地 VS Code 开启终端响铃

打开命令面板，选择「Preferences: Open User Settings (JSON)」，把下面两个设置合并到现有顶层对象中。保留其他设置；如果键已存在，只更新对应值。Remote SSH 窗口也应修改本地 User 设置。

{
  "accessibility.signals.terminalBell": { "sound": "on" },
  "terminal.integrated.enableVisualBell": true
}

如果版本提示不认识 enableVisualBell，在设置中搜索 Terminal Bell / Visual Bell；旧版可能使用 terminal.integrated.enableBell。声音以实际听到为准。

在本地 VS Code 终端运行：

printf '\a'
2 · 在你已登录的 SSH 终端测试

用平常的方式登录服务器，在同一个交互式终端执行。它会显示 SSH / 终端状态，并发送一次响铃。

printf 'SSH=%s\n' "${SSH_CONNECTION:+yes}"
tty
printf '\a'

普通 SSH 应显示 SSH=yes，tty 应返回终端路径。VS Code Remote SSH 的终端可能没有 SSH_CONNECTION，不能仅凭空值判断失败。先在没有 tmux / screen 的会话测试；远端无声音时先解决终端链路。

3 · 在远端启动 Codex 验证一轮任务

在已经登录的服务器终端运行下面的启动命令。参数仅对这次 Codex 会话生效，不写配置文件；正常使用模型产生的费用与平时相同。

codex -c 'tui.notifications=["agent-turn-complete"]' -c 'tui.notification_method="bel"' -c 'tui.notification_condition="always"'

发起一轮任务，完成时应听到终端提示音，再切换窗口验证一次。已有 notify / Stop Hook 仍可能额外提醒；请检查原配置，避免重复通知。

4 · 验证后保存为远端默认设置（可选）

先备份服务器实际使用的 Codex 配置，再将下列设置合并到该文件（通常是 ~/.codex/config.toml；设置 CODEX_HOME 时使用对应目录）。已有 [tui] 块时只更新三个键，不要重复添加整个块，也不要把密钥或完整配置粘贴进回响。

[tui]
notifications = ["agent-turn-complete"]
notification_method = "bel"
notification_condition = "always"

保存后重启 Codex，再次验证。恢复时还原这三个键的原值；本地 VS Code 也可恢复原来的响铃设置。
