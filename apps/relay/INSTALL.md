# 回响 Relay · 首版试用

交付两个产品，配对后使用同一个管理入口。首版桌面端仅支持 macOS Apple Silicon（M 系列芯片），不是 Windows / Intel 安装包。

## 1. 桌面应用

解压 `Relay-0.3.1-mac-arm64.zip`，把 `Relay.app` 拖到「应用程序」后打开。已内置本地服务与独立 Node 运行时，无需安装 Node、运行命令或打开终端。启动默认只显示顶部菜单栏图标，不占 Dock；点击「打开回响」显示管理窗口。关闭窗口后仍在菜单栏运行；菜单栏可重新打开、选择登录时启动或退出。

此版本仅本地 ad-hoc 签名，尚未 Apple 开发者签名或公证。其他电脑可能被 Gatekeeper 拦截；确认来源后，通过「系统设置 → 隐私与安全性」允许打开。不建议关闭全局安全机制。

若提示端口占用，请先关闭旧的回响 Node 服务，再打开应用。桌面服务仅监听 `127.0.0.1:62348`。

## 2. 浏览器扩展

解压 `Relay-Browser-1.4.0.zip` 到固定目录。在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 开启开发者模式，选择「加载已解压的扩展程序」，选中 `relay-browser` 文件夹。此版尚未上架商店，ZIP 不能直接点击安装。扩展与桌面端采用同一套同心环图标。

已经装过开发版的用户应更新原扩展的文件夹并重载，或停用旧版后加载新版，避免两个扩展同时重复提醒。更新后刷新已打开的 AI 页面。

## 3. 配对与试用

1. 打开回响桌面应用，再在扩展小弹窗点击「管理」，进入完整管理页面。小弹窗仅保留常用提醒设置。
2. 管理页面会自动检测本机回响并显示地址。点击「连接此应用」，在桌面确认框选择「允许连接」即可，不用填写地址或复制配对码。只检查默认本机地址及曾成功连接的地址，不扫描端口。
3. 点击「打开统一工作台」管理 CLI 和网页提醒。首次连接只读取浏览器原设置，不自动覆盖。保存网页设置会等待浏览器确认，通常 30 秒内完成。诊断、保活等高级设置也在扩展管理页面。
4. 在 Claude Code、Codex、OpenCode 卡片中「预览并接入」，检查将修改的文件，再确认。软件先备份再合并，不会自动修改任何 CLI 配置。重启对应 CLI 会话让配置生效。
5. 点击测试提醒，再分别让网页和 CLI 完成一次真实任务。macOS 横幅依赖系统通知设置与专注模式；必要时检查脚本编辑器 / terminal-notifier 的通知权限。软件不保证系统一定显示横幅。

当前仅绑定一个浏览器配置；确认新的连接会替换旧连接。可在扩展管理页面断开连接，撤销后扩展仍能独立提醒。扩展不上传对话内容，只向本机同步提醒开关。服务未运行时会提示启动桌面应用，随后可重新检测；已连接的浏览器会自动重连。

## 边界与卸载

- Claude Code、Codex、OpenCode 已实现配置适配；DeepSeek Harness 仅预留入口，不算已接入。
- 桌面端和浏览器使用各自原生通知，不额外建立任务中心、不重复转发同一提醒。
- 退出桌面端会暂停统一管理，但已配置的 CLI 通知脚本和浏览器扩展仍独立工作。
- 本地配置与备份位于 `~/.relay-notifier`，不读取或展示 API Key。首版管理用户级配置，项目级配置若覆盖用户配置，需自行检查。
- 卸载前请先在卡片中「恢复原配置」。若接入后文件又被修改，软件会拒绝直接覆盖，请按备份人工合并。然后解除浏览器配对，退出并移除应用、卸载扩展；确认 CLI 已无回响引用后再清理 `~/.relay-notifier`。
- 不包含自动更新、商店发布或 Apple 公证，属于可本机试用的第一版。

连接后的公共设置支持双向同步：浏览器修改声音、音量或桌面通知会写入本机通知偏好，桌面界面每 5 秒刷新且保留未保存的编辑。首次连接保留双方设置，可主动同步本机偏好。离线期间两端独立工作，本机离线修改可在重连后手动同步；同时修改同一项时，以扩展确认的写入为准。两端音频实现不同，相同音量数值不保证相同响度。

## 4. SSH 远程 Codex 提醒

在桌面管理窗口找到「SSH 提醒」，按步骤复制本地 VS Code 设置、远端响铃测试及 Codex 启动命令。先验证声音，再选择是否保存为远端默认配置。响铃由本地 VS Code 负责，不需要在服务器安装桌面软件；不使用回响系统通知或音量。勾选表示你手动确认，不是自动检测。
