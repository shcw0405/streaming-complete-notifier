# 评委评价整理与项目回应

## 使用说明

以下内容根据 2026 年 8 月 31 日黑客松录音转写整理。录音自动转写存在错字，其中“捉宠”大概率为“桌宠”，“艺人公司”大概率为“一人公司”。因此，展示材料中统一使用“评委意见摘要”，不把整理后的句子标成逐字引语。

项目展示和讨论的大致时间范围为 **24:44–32:25**。

## 评委意见摘要

### 1. 仅做完成提醒，产品差异化还不够强

录音依据：28:40–29:40 左右，评委认为企业内部已经存在将任务状态接入协作工具的做法，并提出“单纯……还是太常见了”。

展示用摘要：

> 单纯的完成通知已经比较常见，项目需要继续寻找更深入的交互价值。

项目回应：

当前版本首先解决跨平台、低打扰和准确检测问题；下一阶段将从“是否完成”扩展到“是否需要人介入”。

### 2. 可以探索更个人化、更具陪伴感的提醒载体

录音依据：28:40–29:27 左右，评委提到偏个人探索时，可以继续向“桌宠”等形式深入。

展示用摘要：

> 面向个人用户，可以进一步探索桌宠、状态角色等更具个性和陪伴感的交互方式。

项目回应：

个性化形象可以降低机械通知的打扰感，但仍应服务于“快速理解状态、立即返回任务”的核心目标。

### 3. 项目的本质是人和 AI 的交互问题

录音依据：29:27 起，评委明确将项目概括为“展示一个人和 AI 的交互的问题”。

展示用摘要：

> 项目真正值得探索的，是人和 AI 之间的交互与协作节奏。

项目回应：

项目定位从“AI 完成提醒器”提升为“人重新介入 Agent 工作流的时机控制”。

### 4. 一人公司场景下，多工具和多 Agent 会带来新的协作问题

录音依据：30:17–31:45 左右。评委描述了一个人同时承担多个工种、使用多个工具和平台的情境，并追问不同上下文如何共享。

展示用摘要：

> 当一个人同时使用多个工具和 Agent 时，需要统一管理任务状态，并让不同环节产生的上下文能够共享。

项目回应：

未来将探索统一任务标识、跨平台状态聚合和可传递的上下文摘要，而不是只在每个网站上独立弹出通知。

### 5. 很多 Agent 任务会在中间状态等待人参与

录音依据：30:17–31:55 左右。评委指出真实任务并非完全自动化，经常需要人在中间节点参与决策。

展示用摘要：

> Agent 并没有完全自动化；执行到中间状态时，经常需要人补充信息或做出决策。

项目回应：

将通知状态从“已完成”扩展为：

- 已完成：回来查看结果；
- 需要输入：补充缺失信息；
- 等待决策：批准、拒绝或选择方案；
- 执行异常：失败、卡住或需要接管。

### 6. 提醒可以成为人参与 Agent 的入口

录音依据：31:55–32:25 左右。评委将“提醒”和“怎么参与进去”联系起来。

展示用摘要：

> 提醒不应只是结果播报，还可以成为人进入任务、完成决策和继续推动流程的通道。

项目回应：

未来通知中可以提供直接操作，例如“批准”“拒绝”“补充信息”“打开任务”，把提醒升级为轻量的人机协作界面。

## 视频中的三张评价卡

建议视频只使用以下三张，保持节奏：

1. **现状判断**：单纯的完成通知比较常见，差异化需要进一步加强。
2. **问题升级**：真正值得探索的是，人应该在什么时候重新介入 Agent 工作流。
3. **未来方向**：提醒可以成为多工具、多 Agent 环境下统一的人类决策入口。

## 不建议采用的表述

- “评委高度认可项目具有巨大商业价值。”录音中没有这一明确评价。
- “评委认为项目非常创新。”评委实际上指出了单纯通知较常见。

- 将自动转写文本不经核对地当作评委逐字原话。
